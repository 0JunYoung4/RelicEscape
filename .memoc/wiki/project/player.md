# 기본 이동 프로토타입

`main.py`는 960×540 내부 화면, 기본 데스크톱 전체화면, 횡스크롤 카메라와 입력·렌더 루프를 관리한다. `configure_display`에서 SDL 논리 해상도를 설정하고 `set_fullscreen`으로 전환한다. F11 창 모드는 1280×720이며, 화면 비율이 다르면 여백을 둔다. 모드 변경에도 카메라의 월드 범위는 유지한다. `draw_scene`은 전체 출력의 여백까지 검은색으로 지운다. `player.py`는 월드 위치, 점프 물리와 애니메이션을 처리한다.

## 동작

- A/D 또는 방향키로 좌우 이동. Shift를 누르면 달린다. 좌우 동시 입력은 정지한다.
- 걷기 300 월드 단위/s, 달리기 525 월드 단위/s. 프레임 경과 시간을 곱해 이동하고 맵 양쪽 64 월드 단위 여백으로 제한한다.
- 키 상태는 이벤트 처리 후 SDL_GetKeyboardState로 읽는다. 창 포커스가 없으면 이동 입력을 0으로 처리한다.
- 기본 바닥 높이는 월드 y=200(화면 y=100)이다. `Player.terrain`의 정적 직사각형과 캐릭터 히트박스로 발판 착지·벽 양면·천장 충돌을 처리한다. 발판에서 걸어 나가면 즉시 낙하한다.

## 점프

- Space KEYDOWN 이벤트로 한 번 점프한다. pico2D가 키 반복 이벤트를 제외하므로 길게 눌러도 자동 연속 점프하지 않는다. 착지 직전 0.10초의 입력은 `jump_buffer_remaining`에 남겨 접촉한 프레임에 소비한다.
- 지상 점프는 바로 수직 속도 900으로 상승한다. 준비 프레임을 건너뛰고 도약 자세부터 표시한다. 중력은 2000이며 각 프레임에 위치를 `v·dt - g·dt²/2`로 적분한다. 최고 높이는 약 203 월드 단위, 공중 시간은 약 0.9초다.
- 수직 속도에 따라 도약·상승·정점·하강·착지 준비 프레임을 선택한다. 새 점프 입력이 없으면 바닥이나 발판에 닿을 때 `land` 자세를 0.12초 표시한다. 착지 모션 중 Space는 즉시 다음 점프를 시작한다. 천장 충돌은 상승을 멈춘다.
- 이후 현재 입력에 맞춰 대기·걷기·달리기로 복귀한다. 공중에서도 기존 좌우 이동·방향 전환·Shift 속도가 적용된다.
- 실제 지지 여부는 `grounded`로 관리한다. 벽에 접촉한 공중에서 새로 Space를 누르면 벽점프한다. 바닥용 입력 버퍼는 착지할 때 소비한다.

## 벽 이동·시험 지형

- `main.TEST_TERRAIN`: 시작 발판 (620,200)-(780,320), 세로벽 (920,200)-(1000,620), 세로벽 (1260,200)-(1340,700), 공중 발판 (1480,460)-(1740,500).
- `_move_horizontal`/`_move_vertical`은 통과한 면을 검사해 위치를 제한한다. 위·아래 이동을 분리해 벽과 천장에 막히고, 떨어질 때 가장 높은 교차 발판에 착지한다. `ground_y`는 기본 바닥이며 발판 높이로 덮어쓰지 않는다.
- `_has_support`는 기본 바닥·발판 윗면 접촉, `_touching_wall`은 지형 측면 접촉만 검사한다. 보이지 않는 맵 끝은 벽점프 벽으로 취급하지 않는다.
- 공중 접촉 방향 `wall_direction`과 입력이 같고 하강 중이며 `_can_wall_slide`의 지지 높이 조건을 만족하면 `wall_slide`로 들어가 최대 120 월드 단위/s로 내려온다. 몸통 바닥부터 높이 140까지 같은 벽이 있어야 높은 손과 아래 발이 허공을 짚지 않는다. 벽 상단 근처에서는 일반 낙하를 유지하다 높이가 확보되면 슬라이드한다. 상승은 보존하고, 입력 해제·벽에서 이탈 시 중력 낙하로 복귀한다. 몸통 측면 접촉만 있어도 벽점프는 가능하다.
- 벽 접촉 중 Space를 누르면 반대 방향 가로 480·위로 820으로 도약한다. `wall_jump_remaining` 0.18초 동안 밀어내기를 유지한 후 입력으로 복귀한다. 같은 벽 재접촉 시 반복 허용은 초기 구현 규칙이다.
- `wall_slide`는 승인한 `wall-slide-right-draft-v4.png`와 JSON의 3프레임을 24fps로 한 번 진행한 후 마지막 자세를 유지한다. 진입할 때 `animation_time`을 0으로 초기화하고, 해제 시 공중 점프 프레임으로 복귀해 지상 준비 자세가 끼어들지 않는다. 벽점프 후 재접촉도 처음부터 재생한다.
- 그림 배율은 140/665, 프레임별 기준점은 (458,701)/(440,704)/(436,704)다. 각 프레임 폭을 553/535/531로 제한해 손 접점을 몸통 오른쪽 경계 x+20에 맞추고 발이 벽 안으로 뚫고 들어가지 않게 한다. 왼쪽 벽은 반전한다. 큰 칼, 높은 손 지지, 굽힌 다리·뻗은 다리와 벽 반대쪽 아래 시선을 유지한다. PNG는 변경하지 않았다. 실제 조작 체감은 추가 확인 대상이다.

## 가로 베기

- X 키로 걷기·달리기·점프 중에 가로 베기를 재생한다. 공격 시간과 방향을 이동 상태에서 분리해 Space와 X를 함께 입력할 수 있고, 베는 동안 중력·이동·충돌을 처리한다. 숙이기와 벽 슬라이드는 해당 자세를 우선한다.
- `attack-right-draft-v2.png`와 JSON의 5프레임을 16fps로 한 번 재생한다. 타격 프레임의 상체를 앞으로 기울이고 칼날을 늘려, 발 기준점에서 칼끝까지 보이는 거리를 약 30% 넓혔다. 왼쪽 공격은 좌우 반전한다.
- 약 0.31초 동안 베기 방향을 고정한다. 지상과 공중은 같은 공격 스프라이트를 사용한다. 피해·공격 판정과 이펙트는 후속 구현이다.

## 숙이기

- S/↓ 유지로 `crouch_time`을 0→0.15초로 진행하고, 놓으면 0까지 되돌린다. 중간 입력 반전에서도 진행 지점을 유지한다. 4프레임 정방향·마지막 유지·역방향으로 표시한다.
- 지상에서만 시작한다. 공중 입력은 착지 연출 이후까지 유지되어야 숙이기로 이어진다. 숙임·일어서기 중 점프 입력은 무시한다.
- 숙임 입력 또는 전환 진행 중에는 이동 속도 90이 Shift보다 우선한다. 완전히 일어서면 기존 걷기·달리기로 복귀한다.
- 완전히 숙이고 실제 x 위치가 변하면 `crawl` 상태로 들어가 별도 8프레임을 초당 8프레임으로 반복한다. 이동 속도는 기존 90을 유지한다.
- 정지·좌우 동시 입력·맵 경계로 실제 이동이 없으면 `crouch`의 마지막 지지 자세로 돌아간다. 키 해제 시 숙이기 진행도를 되돌려 일어서며, 이동 주기를 재생하지 않는다.
- 자세 변경 후보가 지형과 겹치면 이전 진행도를 유지하므로 낮은 천장 아래서 완전히 일어서지 못한다. 숙임으로 폭이 늘어나 벽에 겹치는 경우도 제한한다. 숙인 채 발판에서 벗어나면 공간이 확보된 경우 공중 기본 몸통으로 돌아간다.

## 히트박스

- `Player.get_hitbox()`는 `(left, bottom, right, top)` 월드 좌표를 반환한다. 발 기준 y는 플레이어 y와 같고 x 중심은 플레이어 x다. 그림·정글도·프레임 여백과 독립적이다.
- 서기 40×140, 완전 숙임 100×80 월드 단위이며 `crouch_time / CROUCH_DURATION`으로 크기를 보간한다. 좌우 방향에 따라 영역이 뒤집히지 않는다. 공중에서는 플레이어 y를 따라간다.
- `draw_hitbox(camera)`에서 화면 좌표로 변환해 빨간 테두리를 그린다. `draw_scene(..., show_hitboxes=False)`의 기본값은 숨김이다.
- Ctrl+H KEYDOWN으로 표시를 토글한다. `update_hitbox_visibility`는 좌우 Ctrl과 빠른 누름·해제를 지원하며, 이벤트 순서대로 Ctrl 상태를 해석한다. 반복 키다운은 기존 pico2D 입력 단계에서 제외된다.
- 같은 영역을 발판·벽·천장 충돌에 사용한다. Ctrl+H를 켜면 캐릭터 빨간색과 지형 청록색 경계를 함께 표시한다.

## 카메라

- `CAMERA_ZOOM=1/3`으로 월드 범위 2880×1620을 표시한다. 이전 0.5보다 가로·세로 시야는 각각 1.5배 넓고 캐릭터·지형은 2/3 크기다. 기본 캐릭터 높이는 내부 화면 약 47px이며, 2560×1440 출력에서는 약 124px이다. 전체화면과 F11 창 전환은 유지한다.
- 시험 맵 너비는 `WORLD_WIDTH=6400`이다. 캐릭터가 화면 중앙에 도달하면 카메라가 따라가며 맵 양 끝에서 멈춘다.
- 렌더링 시에만 `(월드 x - 카메라 x) × 배율`, `월드 y × 배율`로 변환한다. 애니메이션 크기와 발 기준점에도 같은 배율을 적용한다.
- `assets/terrain/ruins-floor-blue-fissures-v1.png`의 아래쪽 362px를 기본 바닥 높이 200에 맞춰 그린다. 1200 월드 단위마다 가로 반복하며, 화면 좌표에서 양쪽 타일이 같은 경계 픽셀을 사용한다. Ctrl+H로 바닥 충돌선을 확인한다. 조작·상태 텍스트는 표시하지 않는다.

## 이미지

- 대기: 승인된 concepts/source-v3 원본의 영역을 직접 그린다.
- 걷기: walk-right-v1.png와 JSON, 8프레임·10fps·1.5배.
- 달리기: run-right-v1.png와 JSON, 16프레임·16fps·0.5배.
- 점프: jump-right-draft-v1.png와 JSON, 승인한 4×2 초안 8프레임. 원본을 그대로 저장했고 프레임별 발 기준점으로 시트의 위치 편차를 보정한다. 표시 배율은 140/388이며 물리 단계로 프레임을 선택한다.
- 숙이기: crouch-right-fast-v1.json의 4개 프레임 정의. 원래 1·3·5·8번째 자세를 고르고 배율 140/411과 프레임별 지면 기준점을 적용한다. 기존 PNG·8프레임 JSON은 `assets/sprites/player/reference/crouch-8frame-v1/`에 원본 그대로 보관하고 빠른 정의에서도 이 PNG를 읽는다.
- 기어가기: crawl-right-draft-v2.png와 JSON, 다리 교차 수정 초안 8프레임·8fps 반복. 배율 140/466과 행별 지면 기준점 405/404로 기존 화면 높이에 맞췄다. 승인 원본 PNG를 변경 없이 저장하고 v1은 비교용으로 유지한다.
- 위 이미지별 배율에 카메라 배율을 추가로 곱해 표시한다.
- JSON 좌표는 왼쪽 위 기준이다. 그릴 때 pico2D의 왼쪽 아래 기준으로 변환하고 발 기준점과 배율을 적용한다.
- PNG는 수정하지 않았다. 왼쪽은 임시 반전이므로 전용 에셋이 필요하다.
