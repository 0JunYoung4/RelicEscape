# 런타임 성능 개선 기록

2026-11-27에 실제 게임의 입력·업데이트·렌더링을 조사하고 반복 작업을 줄였다. 기준 코드는 `dea80ae`다. 이동·충돌·전투·레일·유물·장치의 판정과 60fps 프레임 제한은 유지했다.

## 확인한 원인과 변경

- 기존 `pico2d.get_events()`는 호출할 때마다 FPS 창 제목을 만들고 `SDL_Delay(1)`을 실행했다. 게임도 프레임 끝에서 대기하고 제목을 다시 바꿨다. 앱의 `input_events.poll_events()`로 기존 이벤트 순서·반복키 제외·키/마우스/종료 변환을 유지하고, 프레임 대기는 게임 루프 한 곳에서만 수행한다. 제목은 초기화 때 한 번 설정한다. 설치된 pico2D 파일이나 전역 함수는 수정하지 않았다.
- 프로파일에서 정점마다 SDL의 Python 좌표·색상 객체를 생성하는 비용이 컸다. `render_mesh.py`가 SDL 메모리 배치를 먼저 검증하고 동일한 float32/RGBA 바이트를 직접 기록한다. 고정 삼각형 인덱스와 원형 좌표는 크기가 제한된 캐시에 보관한다. 정점 버퍼는 호출마다 독립적으로 만들어 카메라 이동과 중첩 호출에서 오래된 값이 남지 않는다.
- A·B·C 공통 메시와 전투방 조명·중경은 같은 정점 기록과 인덱스를 사용한다. 열별 UV·페이드 값은 행마다 계산하지 않고 한 번 계산해 재사용한다. 화면 또는 현재 클립 영역 밖의 빛은 만들지 않는다.
- `LowerCaves`에서 실제로 사용하지 않던 이미지 다섯 개와 초기 색상 설정을 제거했다. 원본 크기의 RGBA 단순 환산으로 약 24MiB이며, 진입·재시작 때 불필요한 디코딩과 텍스처 생성을 줄인다.
- 소프트웨어 렌더러에서 얇은 발판 클립의 비텍스처 광원 삼각형이 기존 `width invalid` 오류를 만들었다. 해당 클립 광원만 재사용하는 흰 텍셀로 그린다. Direct3D11의 광원 경로는 유지하며, 소프트웨어 경로에서도 현재 블렌드·클립 의미를 보존한다.

이동·적·충돌 갱신만 분리한 초기 측정은 A/B/C 평균 약 0.065/0.091/0.065ms였다. 지속적인 계산 비용을 줄이기 위해 렌더링과 입력 대기를 우선 수정했다. 게임 플레이 규칙이나 물리 구조를 새로 만들지 않았다.

## 측정 조건과 결과

Windows 11, Python 3.13, Direct3D11, 논리 화면 960×540과 실제 출력 2560×1440인 숨김 창에서 측정했다. 각 장면·카메라의 준비 10프레임 뒤 60프레임을 측정하고, 별도 cProfile 8프레임을 기록했다. 비교 대상은 고정된 게임 상태와 같은 카메라 동선이다.

아래 값은 업데이트·그리기 제출·present까지의 **CPU 경과 시간(ms)** 이다. 입력 폴링은 별도로 측정했다. 로딩·캡처·이미지 저장·프레임 대기·vsync·프로파일러 비용은 표에서 제외했다. 숨김 창 present는 GPU 전체 완료나 OS 합성 비용을 측정하지 않으므로 실제 FPS 보장값으로 해석하지 않는다.

| B 정지 | 3.11 | 1.61 | 4.00 | 5.44 |

같은 native 환경에서 입력 폴링 240회는 기존 중앙값 1.9991ms·p95 2.5090ms에서 새 함수 중앙값 0.0011ms·p95 0.0026ms로 줄었다. `SDL_Delay(1)`의 실제 대기는 Windows 타이머 상태에 따라 변했으며, 특정 지연이 항상 발생한다고 단정하지 않는다.

모든 구간의 변동이 줄었다고 주장하지 않는다. B 정지 p95는 이번 표본에서 늘었다. 소프트웨어 렌더러는 큰 반투명 이미지의 픽셀 합성 비용이 지배적이며 A는 약 50ms, C는 약 75~81ms로 남았다. 소프트웨어 C 표본은 이전보다 높아 이 경로의 전반적인 개선으로 보고하지 않는다. 실제 출력 환경과 장시간 전체화면 플레이 체감은 별도 확인 대상이다.

[구간별 중앙값·p95·최댓값·16.67ms 초과 수와 비교 JSON](runtime-performance-results.json)에 두 렌더러의 모든 측정 결과와 메타데이터를 남겼다. 원시 표본·cProfile·PNG는 로컬 `.cache/perf-before`와 `.cache/perf-final`에 저장했다.

## 화면과 기능 검증

Direct3D11의 오프닝·전투방·A·B·C 정지/이동 비교 10장은 이전과 픽셀 해시가 일치한다. 소프트웨어도 전투방 두 장을 제외한 8장이 일치한다. 전투방은 기존 오류가 있던 얇은 반사광 경로를 수정해 채널당 최대 2/255의 색 차이가 생겼다. 두 렌더러의 최종 측정 1,200프레임에서 SDL 오류가 없었다.

정점 바이트 일치와 중첩 호출 독립성, 입력 큐 순서와 반복키 제외, 폴링의 대기·제목 부작용 제거, 창 제목 1회·F11, 얇은 발판 광원 오류를 검사한다. 실제 게임 루프의 이동·점프·베기·피격·사망·유물·레일·장치·재시작 회귀 검사를 함께 실행한다.

최종 전체 테스트는 222개가 통과했다. 실행 시간은 221.569초, 종료 코드는 0이다.

## 재현

```powershell
.\.venv\Scripts\python.exe -B -m tools.profile_gameplay --output-dir .cache/perf-new --compare .cache/perf-before
.\.venv\Scripts\python.exe -B -m tools.profile_gameplay --output-dir .cache/perf-new --events-only
.\.venv\Scripts\python.exe -B -m unittest discover -s tests
```

성능 측정은 테스트나 다른 무거운 작업과 동시에 실행하지 않는다. `--backends native --native-output logical`로 논리 크기 출력만 측정할 수 있으나, 데스크톱 크기의 위 표와 직접 비교하지 않는다. 게임을 실행한 채 파일을 바꿨다면 종료 후 다시 실행해야 새 코드가 반영된다.
