# 하단 A–B 통로의 비석과 공간 깊이

4번 구도의 중앙 비석을 기준으로 장식을 배치했다. 5번 구도에서는 아래 발판에서 같은 공간의 왼쪽 절벽과 근경을 올려다본다. 기준 지형은 [절벽 접합부 수정본](lower-route-ab-terrain-join.md)이고, 각 레이어의 원점과 배율은 그 원화를 따른다.

## 기존 요소의 배치 기준

| 역할 | 기존 요소와 추가 장식 | 색·명암·디테일 | 크기 기준 |
| --- | --- | --- | --- |
| 먼 배경 | 동굴 능선, 아치, 푸른 안개와 천장 윤곽 | 청록과 푸른 공기색에 맞춘 낮은 대비. 아치의 구멍과 능선 윤곽만 크게 읽힌다. 비석 뒤 빈 자리는 주위 공기색으로 복원했다. | 큰 능선과 아치 군집을 화면 수백 픽셀 폭으로 둔다. |
| 중간 배경 | 두 비석, 원래 붙어 있던 뿌리·고사리, 뒤에 심은 부채꼴 잎과 휘는 풀 | 석재 홈과 큰 면의 대비를 남긴다. 새 뒤쪽 잎은 청록 쪽으로 물들여 끝의 실루엣이 주로 보이게 한다. | 새 잎 군집 폭 232–338 월드 단위. 배율 0.5에서 약 116–169 px다. |
| 지형에 붙은 장식 | 비석 오른쪽의 덩굴, 발치 이끼, 비석 아래를 살짝 가리는 둥근 풀 | 어두운 청록 바탕, 잎 윗면의 짧은 이끼빛. 기존 잎과 뿌리의 크기·방향을 반복한다. | 덩굴 폭 72, 이끼와 풀 폭 112–120 월드 단위. 배율 0.5에서 약 36–60 px다. |
| 가까운 전경 | 낮은 휜 풀과 큰 둥근 잎 | 화면 가장자리의 짙은 청록 실루엣. 잎맥과 하이라이트를 낮춰 윤곽이 먼저 읽힌다. | 폭 307·457 월드 단위. 배율 0.5에서 약 154·229 px다. |

## 겹침과 앵커

먼 능선과 아치 위로 비석 군집의 큰 윤곽을 배치했다. 뒤쪽 풀의 뿌리와 잎 일부는 기존 비석과 고사리에 가려지고, 덩굴은 큰 비석의 오른쪽 경계를 감싼다. 이끼와 둥근 풀은 비석의 발치에서 아래 모서리만 조금 가린다. 같은 `grass-rounded-tuft`를 중경에서 크게, 비석 발치에서 작게 뒤집어 배치했다. 비석의 홈과 정상 위 공간, 레일 끝과 절벽 착지면, 아래쪽 두 전경 사이를 비워 뒀다. 아래층 왼쪽 풀 밑동은 보행선 `y=-244` 직전에 닿고, 오른쪽 큰 잎은 통로 아래의 암반 음영에 붙는다.

원본의 원경·비석·지형 판은 990 × 724에 같은 원점을 공유한다. 새 장식은 자산의 투명 여백을 제외한 `visible_bounds`와 뿌리 또는 줄기의 `pivot_px`를 사용한다. 렌더러는 앵커를 원화 픽셀에서 월드 좌표로 옮긴 뒤 지형과 같은 `camera.world_to_screen`을 적용한다. 화면에 고정된 위치나 시차는 추가하지 않았다.

장식의 색과 밝기는 `SDL_SetTextureColorMod`로 조절한다. 예를 들어 같은 둥근 풀에 뒤쪽은 `(75, 199, 255)`, 비석 발치는 `(154, 238, 230)`의 RGB 곱을 적용한다. PNG 알파는 잎 윤곽과 여백을 처리하며, 원경의 방 경계 페이드는 기존 알파를 사용한다. 비석 뒤 식생의 거리감은 색과 대비로 만든다.

## 다른 방에서 사용

1. 보행선과 절벽 끝을 고정하고, 단색 실루엣으로 가려질 부분과 비워둘 시야를 먼저 고른다. 홈이나 발광 목표, 다음 착지점이 큰 형태에 묻히지 않는지 본다.
2. [비석 장식 배치](../lower_route_passage_art.py)의 `BEHIND_STONE`, `ON_STONE`, `NEAR_BANK`에서 같은 식생의 색·크기·방향을 바꿔 쓴다. `PassageArt`에 새 방의 공용 원점과 배율, 같은 크기의 `backdrop.png`·`monument.png`·`terrain.png` 폴더, 그리고 새 앵커를 넘긴다. [이끼 바닥 장식](../assets/terrain/moss-grotto-floor-decor/README.md)과 [동굴 식생](../assets/terrain/moss-grotto-foliage/README.md)의 배치 메타데이터를 사용한다.
3. 원경 → 뒤 식생과 비석 → 지형 → 부착 장식 → 근경 순으로 그린다. 이 통로의 근경은 암반 앞에 낮게 놓고 플레이어·적·유물·흔적보다 먼저 그려 게임 신호에 그리기 우선권을 준다. 기존 레일과 착지면에 전경 실루엣이 닿는지 위층과 아래층에서 각각 확인한다.
4. 실제 원화의 레이어를 다시 만들려면 `python -m tools.bake_lower_route_ab_depth`를 실행한다. `LowerRouteConnection.draw_layer(camera, height, layer)`의 `far`, `middle`, `terrain`, `attached`, `near`로 합성 전후에 각 역할을 같은 카메라에서 검수할 수 있다.

## 검증

- SDL 소프트웨어와 Windows Direct3D 11에서 논리 해상도 960 × 540, 배율 0.5로 비교했다. 고정 카메라 원점은 4번 `(4272, -270)`과 5번 `(3352, -740)`이다.
- 양방향 주행 362프레임의 위치·접지·카메라 좌표와 배율이 기준 버전과 일치했다. 절벽에서 49프레임 뒤 아래층 `y=-244`에 착지했다. 카메라를 월드 `(+128, +64)`만큼 옮겼을 때 부착 장식은 화면에서 `(-64, +32)` px 이동했다.
- 두 시점의 상하층 착지면 5,014픽셀과 레일 발광 중심부가 기준 버전과 일치했다. 플레이어·적·유물·흔적에 실제 스프라이트를 사용한 별도 화면에서도 근경에 가린 픽셀은 없었다. 적은 확인용 위치에 배치했다. 전체화면 수동 키보드 플레이는 수행하지 않았다.
